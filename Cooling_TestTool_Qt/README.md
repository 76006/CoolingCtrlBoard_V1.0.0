# 冷媒罐循环泄压上位机

## 连接并开始试验

1. 使用工作区的配套循环试验 App。已有匹配 Bootloader 的板卡使用 `Cooling_TestTool_RTthread/output/cooling_app.bin`，App 地址为 `0x08008000`。首次装机按固件工程中的下载和 UID 配置说明操作。
2. USB 转 **3.3 V TTL** 接 USART1。转接器 RX 接板端 PB6/TX，TX 接 PB7/RX，两端 GND 相连。关闭占用同一 COM 口的串口助手。
3. 在 `Cooling_TestTool_Qt/release` 打开 `CoolingRelief.exe`，复制到其他电脑时复制整个 `release` 文件夹。选择 COM 口并连接。握手成功后可观察压力、泄压口 NTC0 和罐体 NTC1，板端保持停热。
4. 输入试验参数并选择记录目录。在现场允许的工作范围内设定最高压力。固件握手报告的硬截止值是配置上界。NTC0 的降幅、回升幅度及确认时长需依据实际探头的温度曲线填写。
5. 点击“开始试验”。软件先建立记录目录，核对下位机回显的整组参数，再发送启动命令。连续完成设定轮数后自动结束。点击“停止试验”可提前停热并保存已经取得的记录。

## 参数与阶段

| 设置 | 用途 |
| --- | --- |
| 最高压力、回压目标、回压容差（MPa） | 原始或滤波压力达到最高压力即停热。收到开始命令并取得有效采样后直接加热到最高压力。回压目标只用于泄压后，留空时采用启动后的首个有效压力采样。 |
| 调温方式 | 循环试验和手动加热共用此选项。满功率调温在允许加热时连续输出 100%；分段 PWM 调温按与目标压力的差值，以 1 秒为周期分段输出 30%、20% 或 10%。达到停止条件即停热。 |
| 最高温度（NTC1，℃） | 自动循环取罐体 NTC1 原始和滤波温度的较高值。距离设定上限 4℃ 时，分段 PWM 占空比最多为 10%；距离上限 2℃ 时，两种模式都暂停加热，回落到上限以下 3℃ 且仍需升压时补热。控温期间继续监测泄压、记录采样。手动模式达到设定温度时结束。板端 70.0℃ 硬截止仍会中止试验。 |
| 温降观察窗口、触发降幅、开始确认时长 | 每份新采样比较 NTC0 与窗口起点的温度。达到降幅先停热并锁存压力，再用同一参考温度确认泄压。温降未持续时中止本次试验，保留候选记录供复查。 |
| 停止回升幅度、停止确认时长 | 从泄压后的最低 NTC0 温度计算回升幅度。回升持续满足条件后记录泄压停止。 |
| 回压稳定时长 | 确认泄压停止后，压力持续位于回压目标 ± 容差内并达到此时长，才完成本轮。 |
| 达上限观察时长 | 达到最高压力后持续停热并等待温降。观察期内始终无泄压则记为“达上限未检出泄压”并结束。 |
| 单轮最长时长、试验轮数 | 限制每轮试验时间和总轮数。超时停热。 |

下位机每 100 ms 采样，50 ms 控制加热。启动后若持续 1.5 秒没有新采样成功写入记录，Qt 请求停热并停止续发加热心跳。板端心跳超时约 3 秒会中止试验。采样失效、超温、超压、OTA 或关闭命令同样可使试验中止。重新连接后可接收板端内存中尚未确认的事件。设备断电后的历史记录以电脑已写入的文件为准。

泄压口 NTC0 使用 TDK NTCG163JX103DT1S 温阻表。低于 −40℃ 时按 −40℃ 和 −35℃ 两个冷端点外推，继续记录泄压、回温及压力。Qt 在实时数值、事件表和曲线中标明低温估算；CSV 保留数值，估算边界记录在同目录的 `parameters.json` 中。原始或滤波 ADC 达到 4091～4095 的近满量程区域时，输入与断线难以区分，固件会按无效处理。

## 工装手动加热

连接协议 2 的配套固件后，设置最高压力和 NTC1 最高温度，点击“手动开启加热”。板端在首次有效采样后按所选调温方式加热；点击同一位置的“关闭手动加热”可立即请求停热。手动加热与自动试验互斥，采样和停止原因都记入所选目录。达到任一设定上限即结束手动加热，再次开启需要重新点击。工装模式的 LS 限位开关仅用于显示罐体状态，允许空接。

## 读取结果

每次试验有独立的“日期时间_试验号”文件夹。

| 文件 | 内容 |
| --- | --- |
| `samples.csv` | 板端采样序号、毫秒时间、轮次、状态、压力、两路温度、有效位和加热状态。失效通道留空。 |
| `events.csv` | 每次事件的时间、压力、温度、轮内峰值、持续时间、结果、发生阶段及通道有效位。失效读数留空。用同一试验号、轮次和事件序号定位。 |
| `curve.png` | 全试验时间范围内的压力、温度与事件标记。正常结束或收到终止事件时有采样即自动生成，也可用“导出曲线 PNG”另存。 |
| `parameters.json`、`session.log` | 本次设置和串口配置应答、断线恢复等运行记录。 |

在 `events.csv` 中筛选 `OPEN` 即可查看**每一次经 NTC0 确认的泄压压力**。该行的时间和压力取自首次满足温降条件的样本。`CLOSE` 给出回温确认时刻及该次泄压持续时间，`ROUND` 给出回压完成时的整轮峰值。同轮再次泄压会有新的 `OPEN` 记录。横轴按板端时间绘制，采样序号不连续处断线。停热后的压力变化也会进入曲线和峰值记录。

## 从源码构建

Qt Creator 打开本目录的 `CMakeLists.txt`，选择 Qt 6.5.3 Desktop MinGW 64 位套件。需要 Qt Widgets 和 Qt SerialPort。命令行也可在已配置该套件与 CMake 的终端中运行：

```powershell
cmake -S Cooling_TestTool_Qt -B build-qt -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=D:/Qt/6.5.3/mingw_64
cmake --build build-qt --parallel
ctest --test-dir build-qt --output-on-failure
```

固件默认为循环试验模式。在配好 Studio 工具链的固件工程目录执行 `scons -j4`。验证正常控制模式可执行 `scons -j4 cooling_test_mode=0`；两种模式共用导出位置，交付循环固件前重新执行默认构建。软件回放与板卡实测应分别记录，实际探头响应延迟、余热产生的峰值和合适的阈值由台架验证。
