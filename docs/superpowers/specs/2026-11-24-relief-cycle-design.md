# 冷媒罐循环泄压试验设计

设计稿，2026-11-24。操作者已选择方案 A。本文中的串口连接、异常结束策略与文件格式为实现建议。

## 测试台与判据

试验以加热升压，泄压口 NTC0 的降温表示可能开始泄压，随后缓慢回温表示可能停止泄压。停热后压力自然回落。NTC1 记录罐体温度。一次试验可以连续运行多轮，操作者需要找出每次泄压时的压力，并能从温压曲线上复核。

方案 A 比较同一探头在一段时间内的温差，可以适应各轮不同的起始温度。方案 B 使用固定温度门槛，配置更简单，但依赖各轮温度条件一致。本次选用 A。界面和报告将判定结果标为“NTC0 判定”，注明时间对应探头的响应。

## 一轮试验

| 阶段 | 进入、动作和完成条件 |
| --- | --- |
| 等待开始 | 专用循环测试固件上电保持停热。Qt 打开串口、核对协议、创建记录文件，板端确认完整参数后方可开始。 |
| 取得初始压力 | 停热采样，待温度观察窗口填满、压力在稳定时间内的极差不超过回压容差，取这段平均压力为整次试验的初始值。手动指定初始压力时，要求实测压力持续在其容差带内。初始压力加容差须小于最高压力。 |
| 加热升压 | 复用下位机现有分段加热控制。若本次 NTC0 较观察窗口起点降温达到触发降幅，立即停热，锁存此时的时间、滤波压力、两路温度及轮内峰值。另行比较原始压力和滤波压力中的较大值，任一达到最高压力就停止加热，本轮持续禁热。 |
| 确认开始 | 以触发时的窗口起点温度作固定参考。温降在确认时长内持续达标，登记一次泄压，开始时间和压力取首次触发样本。短暂温降未通过确认时，记录“温降未确认”、停热结束本轮并暂停试验，供操作者复核。 |
| 达上限后观察 | 未触发温降就达到最高压力时保持停热，继续按同一温降规则监测。观察期内出现的候选也可完成开始确认。期满无候选则记“达上限未检出泄压”，暂停。上限和温降在同一样本触发时，两者都记录。 |
| 确认停止 | 从首次触发样本起跟踪最低 NTC0 温度。温度高出该最低点达到回升幅度，并连续保持到停止确认时长，登记停止时刻、压力和持续时间。条件中断则重新计时。 |
| 自然回压 | 保持停热。确认停止后清空上次温降窗口，从当前 NTC0 温度重新积累温降，填满后恢复滚动比较。压力连续处于初始压力 ± 容差且持续满稳定时长，才完成本轮。若同一样本又出现合格温降，优先处理新候选，按同一轮的新事件重新确认停止和回压。 |
| 轮次结束 | 达到设定轮数后停热结束；尚余轮次则使用原初始压力开启下一轮。人工停止、超时或故障均停热，记录当时的轮次和阶段，重新开始必须由操作者发出命令。 |

每轮记录首次触发时压力、截至触发的峰值及整轮最终峰值。最高压力用于停热判断，停热后的余热可能使实测峰值继续上升，应保留这些样本。程序按新的 100 ms ADC 快照更新判据，以板端时间计时；50 ms 控制任务重复读取同一快照时不重复计数。

## Qt 上位机

建议使用本机具备的 Qt 6.5.3 MinGW、Widgets 和 SerialPort，在工作区新增独立桌面工程。首版经 USB 转 TTL 接板上 USART1，115200、8-N-1。窗口提供串口连接、参数、开始和停止、同步曲线和逐轮事件记录。

| Qt 可设项目 | 单位或行为 |
| --- | --- |
| 最高压力、初始压力、回压容差 | MPa，显示三位小数。初始压力可选实测或手动。最高压力须低于板端硬截止值。 |
| 温降观察窗口、开始确认时长、停止确认时长 | 秒，分辨率与 100 ms 采样周期匹配。 |
| 触发降幅、停止回升幅度 | ℃，分辨率 0.1 ℃。 |
| 压力稳定时长、达上限后观察时长、单轮最长时长 | 秒。稳定时长用于初始压力采集和回压确认。单轮时限覆盖升压、泄压、回压；初始压力采集也使用该时限。 |
| 试验轮数、保存位置 | 正整数轮数；操作者选择试验文件夹。 |

两端都校验参数，板端返回接受值和错误原因。试验期间锁定生效参数。协议报告固件支持的设置范围。允许在空闲时观察曲线以便选择现场判据；首次运行要求操作者输入试验最高压力和判据，保存过的参数可复用。

压力用 MPa 轴，NTC0 和 NTC1 共用 ℃ 轴，横轴使用板端相对时间。标记候选开始、确认停止、达到上限、回压完成与异常。每次试验建立独立目录，连续写入 UTF-8 采样 CSV 和事件 CSV，保存生效参数。采样 CSV 保留时间、序号、轮次、状态、压力、两路温度、有效位和加热状态。事件 CSV 保留事件序号、轮次、关联时间与压力、峰值和结果。结束或中止时可导出含完整时间范围的 PNG。缺失样本在曲线上断开，文件写入失败时请求停热并提示记录中断。

## 下位机与通信

在现有 RT-Thread 测试工程内增加循环试验模式。使用同一份 ADC 快照及两路各自已有的温阻表进行换算；NTC0 用于泄压检测，NTC1 用于记录及原有温度保护。循环状态机在压力控制输出前裁决 PWM，统一加热模块仍是唯一的 GPIO 写入者。试验模式独占加热许可，串口旧命令及 CAN 开启命令不能绕过等待、停热或故障状态；关闭命令始终生效。正常固件与原有 CAN、OTA 报文保持兼容。

保留 UID、罐体、标定、OTA 和采样新鲜度联锁；循环模式启用板端独立超温、超压截止，并识别传感器断线和越界。联锁触发即停热并中止当前试验。最高压力和检测参数由 Qt 下发，板端硬保护上界由固件约束。阈值需通过实际试验条件确定，传感器满量程仅用于换算。

串口在现有控制台上提供带前缀的试验命令与独立数据行，区分普通控制台输出。握手获得版本和设备状态，参数整组提交，启动与停止有应答，遥测带采样序号，事件带试验标识与事件序号。重复命令或重复事件不得重复开测或新增记录。Qt 用心跳表明仍在记录；板端心跳超时则停热中止，重连后回读状态和未确认事件，显示中断。板端复位后回到空闲，Qt 将旧试验标记为中断。串口消息组帧与磁盘写入不阻塞压力控制任务。

## 验收

1. 以合成的同步压力、NTC0、NTC1 样本跑过两轮完整试验。核对首次触发压力、触发前与整轮峰值、缓慢回温、自然回压和第二轮启动时刻。
2. 分别覆盖瞬时温降、回温中断、回压时再次泄压、达到上限后延迟泄压、始终无泄压、压力已经复原但温度仍未回升。核对每种情形下的事件数和加热输出。
3. 检查断线、重复命令、复位、采样陈旧、拔罐、人工停止与文件写入失败。核对下位机停热、Qt 显示结果以及已写记录可读。
4. 编译 Windows Qt 程序、RT-Thread 循环试验固件，并检查正常固件构建。软件回放可验证流程，探头响应延迟、可用判据、回压容差和实际停热后峰值须通过台架实测确认。
